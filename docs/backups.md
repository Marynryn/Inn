# Резервные копии

Весь сайт — это папка `STORAGE_DIR` на томе Railway:

| Что               | Где                    |
| ----------------- | ---------------------- |
| база SQLite       | `db.sqlite` (+ `-wal`, `-shm`) |
| epub глав         | `epubs/`               |
| аватарки          | `avatars/`             |
| рамки, скины      | `frames/`, `skins/`    |
| картинки барабана | `reel/`                |

Код лежит в репозитории, а всё перечисленное — только на томе.

## Три уровня защиты

1. **Ночной снимок базы** — сам сайт, задача `backup-db` в 03:43 МСК
   (`server/tasks/backup-db.ts`). Пишет `backups/db-<время>.sqlite.gz`, хранит
   последние 7. Спасает от порчи базы, неудачной миграции и случайного
   удаления. Лежит на том же томе — от потери тома не спасает. Список снимков
   виден в панели: «Аккаунт» → «Резервные копии».
2. **Полная копия по кнопке** — «Аккаунт» → «Резервные копии» → «Скачать
   полную копию» (`GET /api/admin/backup`). Zip с `db.sqlite` и всеми папками
   файлов. Это единственная копия вне Railway — скачивать к себе регулярно,
   хотя бы раз в неделю и перед крупными изменениями.
3. **Снимки тома в Railway** — сервис → вкладка Backups → включить расписание.
   Снимают весь том целиком, восстанавливаются там же кнопкой Restore.
   Включаются в настройках Railway, из кода их не завести.

## Восстановление

### Из снимка тома Railway

Backups → нужная дата → Restore → Deploy. Railway подключит восстановленный
том вместо текущего (текущий не удаляется) и перезапустит сервис.

### Из полной копии (zip) или ночного снимка

1. Распаковать: из zip — `db.sqlite` и папки; ночной снимок —
   `gunzip db-….sqlite.gz` и переименовать в `db.sqlite`.
2. Остановить сайт (иначе он продолжит писать в старую базу).
3. Положить `db.sqlite` и папки в `STORAGE_DIR`, **удалив** старые
   `db.sqlite-wal` и `db.sqlite-shm` — журнал от прежней базы к новой не
   подходит.
4. Запустить сайт. Миграции при старте доведут схему до текущей, если копия
   старше кода.

На Railway файлы на том проще всего положить через `railway ssh` в сервис с
этим томом.

Проверка без риска — локально:

```bash
mkdir -p /tmp/restore && cd /tmp/restore && unzip ~/Downloads/taverna-backup-*.zip
STORAGE_DIR=/tmp/restore npm run dev
```

Сайт поднимется на копии; войти можно тем же паролем, что на боевом.
